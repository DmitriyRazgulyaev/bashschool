# Как добавить языковую пару (Go + Vue + PostgreSQL)

## Из панели администратора

1. Войти под администратором (создаётся при первом запуске из `ADMIN_EMAIL` / `ADMIN_PASSWORD`).
2. Открыть **Модерация → Управление языковыми парами**.
3. Заполнить коды исходного и целевого языка: `ba`, `en`, а также название **Башкирский → Английский**.
4. Нажать **Добавить**. Список языковых пар теперь берётся из `language_pairs` в PostgreSQL.
5. На той же странице создать материал или использовать существующий. Создать фрагмент на исходном языке `ba` (для английского источника указать `en`).
6. После сохранения фрагмента выбрать новое направление `ba-en` и ввести **предложенный перевод**. Повторять для нужного количества фрагментов.
7. Ученик выбирает `ba-en` при регистрации, в профиле или на странице урока. Telegram использует пару из профиля.
8. Если нет хотя бы одного фрагмента с вариантом перевода, `GET /tasks/daily?langPair=ba-en` вернёт `404` с кодом `NO_TASKS_FOR_PAIR` — это ожидаемо.

## Управление через HTTP API

`GET /api/v1/language-pairs` — публичный список активных направлений.

Для администратора (JWT обязателен):

```http
POST /api/v1/admin/language-pairs
Content-Type: application/json
Authorization: Bearer <token>

{"sourceLang":"ba", "targetLang":"en", "name":"Башкирский → Английский"}
```

```http
PATCH /api/v1/admin/language-pairs/ba-en
Content-Type: application/json
Authorization: Bearer <token>

{"active":false}
```

Отключённые пары сохраняются в базе вместе с заданиями и переводами, но исчезают из публичного списка и не выдаются в новые задания.

## Миграции и сохранение старой базы

- `db/001_init.sql` — первоначальная схема и демоданные.
- `db/002_language_pairs.sql` — справочник пар, исходный язык фрагментов и внешние ключи.
- Обе выполняются при запуске API; обновление `002` написано идемпотентно.
- **Нельзя запускать `docker compose down -v`**, если нужно сохранить данные.
- На случай ошибки сделайте `pg_dump` перед обновлением.

## Ограничения

- Новое направление само по себе **не переводит тексты автоматически**. Нужно добавить исходные фрагменты и варианты перевода.
- Семантическая проверка синонимов и экспертная валидация не автоматизированы.
- Поле `text_ba` в старой схеме сохраняется для совместимости. Для фрагментов других языков исходный язык берётся из `source_lang`.
- Текущая схема ориентирована на пары из двух- или трёхбуквенных кодов (`ba`, `ru`, `en`, `kk`). Для региональных тегов вроде `pt-BR` понадобится расширение валидатора и схемы.
