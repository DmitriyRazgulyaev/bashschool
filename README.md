# ТелемКүпер — Башкирская языковая школа

Веб-платформа для ежедневной проверки и исправления переводов с расширяемыми языковыми парами с XP, сериями занятий, рейтингами школ и классов, Telegram-ботом, экспортом результатов и модерацией. Интерфейс **вдохновлён игровыми принципами Duolingo**, но визуально и функционально является самостоятельной разработкой (без их логотипов и ассетов).

## Ежедневные цели и переводы (обновление)

Вместо ограничения **одним упражнением в день** доступны последовательные переводы и три ежедневные цели:

| Цель | Условие | Бонус (сверх базовых 10 XP за упражнение) |
| --- | --- | --- |
| Первые 3 перевода | Завершить 3 упражнения | +50 XP |
| Мастер переводов | Завершить 5 упражнений | +100 XP |
| Внимательный переводчик | Отправить 1 исправление | +25 XP |

Все цели могут выполняться в один день; награды суммируются, но **каждая начисляется один раз**. Прогресс учитывает упражнения во всех языковых парах пользователя. Начало следующего дня — 00:00 UTC (дата PostgreSQL). Награды начисляются автоматически внутри одной транзакции с сохранением ответа.

- `GET /api/v1/daily-quests` — цели и прогресс на сегодня.
- `GET /api/v1/tasks/daily?langPair=ba-ru` — следующее незавершённое упражнение; после ответа можно запросить следующее в тот же день.
- `POST /api/v1/tasks/:id/answers` — теперь возвращает `baseXp`, `questBonusXp`, `xpEarned`, `unlockedQuests`.
- Telegram: `/daily` — следующий перевод, `/quests` — цели дня.

**Обновление существующего проекта:** извлеките ZIP поверх исходников, сохраните старый `.env` и запустите `docker compose up --build -d`. Миграция `db/003_daily_quests.sql` применяется при запуске backend, не удаляя существующие ответы и XP. Перед заменой кода рекомендуется сделать резервную копию БД. **Не выполняйте `docker compose down -v`**.

## Быстрый старт (Docker)

Требуются Docker и Docker Compose. При **первом** запуске нужен интернет для загрузки образов и зависимостей.

```bash
cp .env.example .env
```

Для PowerShell на Windows: `Copy-Item .env.example .env`.

Отредактируйте `.env`: задайте уникальные `POSTGRES_PASSWORD`, `JWT_SECRET` (не менее 32 символов), `ADMIN_EMAIL`, `ADMIN_PASSWORD` (не менее 12 символов). Для Telegram при желании добавьте `TELEGRAM_BOT_TOKEN`, полученный в @BotFather. **Никогда не публикуйте .env и токен бота в Git.**

```bash
docker compose up --build -d
```

Адреса:
- Сайт: **http://localhost:5173**
- REST API: **http://localhost:8080/api/v1**
- Проверка сервера: **http://localhost:8080/health**
- API-контракт: `docs/openapi.yaml` (можно открыть в Swagger Editor)

Остановка:

```bash
docker compose down
```

`docker compose down -v` **удалит базу данных** — используйте осторожно.

### Вход в администратора

Если указаны `ADMIN_EMAIL` и `ADMIN_PASSWORD`, при первом старте backend создаст администратора. Войдите этими данными на сайте. Существующему аккаунту с таким email роль автоматически не повышается.

Вкладка **Модерация** позволяет добавить источник, фрагмент, а затем исходный вариант перевода для заданий. На этой же странице администратор может назначить роли `teacher` и `moderator`, указав UUID пользователя из его профиля. Текущие учебные фразы загружаются автоматически (демонстрационные данные).

## Новое: добавление языков без изменения исходников

**Языковые пары хранятся в PostgreSQL, а не в Go-коде.** Администратор может создавать направления в разделе **«Модерация» → «Управление языковыми парами»**, например `ba-en` (Башкирский → Английский). Указываются `sourceLang`, `targetLang`, `name`. Статус можно менять кнопкой «Включить/Отключить», название редактировать.

- Публичный API: `GET /api/v1/language-pairs` — только активные пары.
- Администратор: `GET /api/v1/admin/language-pairs`, `POST /api/v1/admin/language-pairs`, `PATCH /api/v1/admin/language-pairs/:code`.
- В регистрации, настройках профиля и экране урока можно выбрать любую активную пару. Бот использует текущую пару из профиля.
- **Добавление языковой пары само по себе не создаёт переводы.** Чтобы появились задания, модератор создаёт фрагмент на исходном языке (поле «Код языка»), после сохранения выбирает языковую пару с тем же исходным языком и добавляет вариант перевода.
- Когда контент для пары ещё не загружен, `/tasks/daily` возвращает `404 NO_TASKS_FOR_PAIR` с пояснением. Данные и голоса разных языковых пар не смешиваются.
- Обратные направления, например `ru-ba`, также возможны, но для них нужны отдельные исходные фрагменты на русском языке.

### Обновление уже запущенной версии — без потери базы

Файл `db/002_language_pairs.sql` идемпотентен. Backend сначала выполняет старую инициализацию `001_init.sql`, затем обновление `002_language_pairs.sql`. Он добавляет таблицу языков и поле `source_lang` в фрагменты, оставляя пользователей, задания, ответы и подтверждённые переводы на месте. Старые фрагменты получают исходный язык `ba`.

После замены файлов в папке проекта:

```powershell
docker compose up --build -d
```

**Не выполняйте `docker compose down -v`: команда удаляет данные PostgreSQL!** Рекомендуется предварительно сделать резервную копию базы. Например, при запущенном контейнере:

```powershell
docker compose exec -T db pg_dump -U bashkir -d bashkir > bashkir-backup.sql
```

В примере `bashkir` — стандартные имя пользователя и база; если они отличаются в `.env`, замените их на свои.

### Пример вызова API добавления пары

```http
POST /api/v1/admin/language-pairs
Authorization: Bearer <админский JWT>
Content-Type: application/json

{"sourceLang":"ba","targetLang":"en","name":"Башкирский → Английский"}
```

Ответ `201` содержит созданную пару с `code: "ba-en"` и `active: true`.

## Использование

1. Создайте аккаунт с ролью ученика на сайте.
2. Откройте «Задания» и подтвердите или исправьте предложенный перевод.
3. Система сохранит ответ и начислит 10 XP за упражнение. После этого можно получить следующий перевод в тот же день; каждая дневная цель принесёт дополнительный бонус один раз.
4. После минимум **5 уникальных пользователей**, если за один вариант проголосовали **≥80%**, он попадает в библиотеку подтверждённых переводов. Неоднозначные результаты передаются в список модерации.
5. Откройте «Переводы» и выгрузите подтверждённую базу в JSON или CSV.
6. Преподаватель может создавать классы, добавлять учеников по UUID и просматривать успеваемость. Школы для демо уже созданы.

Важно: согласование в MVP выполняется **по точному совпадению текста** после сохранения варианта. Продвинутая семантическая группировка синонимов, полноценный машинный перевод, TTS и распознавание аудио — будущие улучшения.

## Telegram-бот

1. Добавьте `TELEGRAM_BOT_TOKEN` в `.env` и перезапустите API: `docker compose up -d --build api`.
2. На сайте откройте «Профиль» → «Получить код привязки».
3. Отправьте вашему боту `/start КОД` в течение 15 минут.
4. Доступные команды: `/start`, `/daily`, `/quests`, `/profile`, `/cancel`.
5. Для перевода нажмите кнопку «Подтвердить» или «Исправить». При исправлении отправьте свой текст.

Бот и сайт пользуются одними заданиями и сохранённым прогрессом. Для работы бота не требуется webhook/публичный HTTPS: используется long polling.

## Разработка без Docker

1. Запустите PostgreSQL и создайте базу/пользователя.
2. Установите Go 1.23+, Node.js 22+ и npm.
3. Запуск Go API из `backend/`:

```bash
export DATABASE_URL='postgres://bashkir:bashkir@localhost:5432/bashkir?sslmode=disable'
export JWT_SECRET='use_a_strong_random_secret_with_32_or_more_characters'
export MIGRATIONS_PATH='../db/001_init.sql'
export LANGUAGE_MIGRATION_PATH='../db/002_language_pairs.sql'
go mod tidy
go run .
```

4. Запуск Vue-приложения из `frontend/`:

```bash
npm install
npm run dev
```

5. Проверка сборки frontend: `npm run build`.

На Windows вместо `export` используйте переменные среды PowerShell (`$env:VARIABLE = 'value'`).

## Границы текущей версии

Выполнен **расширенный MVP**, но не промышленная система. На следующем этапе необходимы:
- Полноценные интеграционные/e2e-тесты с работающей PostgreSQL и Telegram sandbox.
- Refresh-токены, восстановление пароля, подтверждение почты, rate limiting, audit log.
- Переводы для других языковых пар, качественный машинный перевод, TTS, мультимедийная загрузка и разметка аудио.
- Семантическая проверка синонимов и экспертный кабинет с расширенными функциями.
- Переход с выполнения SQL-файла при старте на версионированный инструмент миграций.
- Защита для публичного развёртывания: HTTPS, секреты, резервное копирование, мониторинг, настройки CORS, полный security review.

**Известное ограничение:** UTC-серия дней рассчитывается сервером БД; при интернациональном использовании нужно учитывать локальный день пользователя. Обновления переводов синхронны в той же транзакции, для большого объёма нагрузки нужен outbox и очередь.

## Новое: импорт произведений и AI-черновики (версия 004)

Администратор: **Модерация → Загрузка художественных произведений**. Введите автора,
название, источник прав (лицензия или разрешение), выберите исходный язык,
режим нарезки **предложения / абзацы**, загрузите UTF-8 `.txt` (до 1 МБ)
или вставьте текст. Подтвердите наличие прав и право обработки материала сторонней моделью.

Импорт создаёт до 500 **черновиков** с байтовыми координатами в оригинальном тексте.
Текст сохраняется в PostgreSQL в `materials.body`, поэтому координаты могут быть проверены.
Черновики не показываются в ежедневных упражнениях, пока администратор их не проверит.

Для кнопки **«Сгенерировать ИИ»** задайте в своём `.env`:

```env
AI_API_KEY=your_api_key_here
AI_API_URL=https://api.openai.com/v1/chat/completions
AI_MODEL=gpt-4.1-mini
```

Секрет передаётся **только** backend-контейнеру. API должен быть совместим с
Chat Completions и `response_format=json_object`. Модель отправляет
предположительно корректный и намеренно неверный перевод. Оба варианта
требуют **ручной проверки администратором**; ИИ не гарантирует точность
перевода с башкирского. Генерация выполняется по одному фрагменту, по кнопке,
а не массово при загрузке. При отсутствии ключа импорт и список черновиков
работают, а кнопка ИИ выдаёт сообщение о необходимости настроить ключ.

Фрагменты публикуются только по кнопке **«Опубликовать»**, после проверки
версий администратором. Статусы: `draft` → `published` или `rejected`.
Участвовать в рейтингах администраторы теперь не могут — роль `admin`
исключена на уровне SQL во всех вариантах рейтинга.

Новые маршруты (все доступны только роли admin):

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/api/v1/admin/literature/import` | multipart: `file` TXT или `text`, `title`, `author`, `license`, `copyrightNote`, `sourceLang`, `segmentMode`, `rightsConfirmed=true` |
| GET | `/api/v1/admin/literature/drafts?langPair=ba-ru` | список черновиков и ранее сгенерированных предложений |
| POST | `/api/v1/admin/literature/fragments/{id}/generate?langPair=ba-ru` | запрос к ИИ, сохранение вариантов |
| POST | `/api/v1/admin/literature/fragments/{id}/publish` | JSON `{ "languagePair": "ba-ru" }` — публикация |
| POST | `/api/v1/admin/literature/fragments/{id}/reject` | отклонение |

### Обновление без потери данных

Сохраните исходный `.env` и том PostgreSQL. Архив заменяет код,
а миграция `db/004_literature_ai.sql` автоматически выполняется при запуске API.

```powershell
cd F:\bashkir-school
docker compose up -d --build
```

Не запускайте `docker compose down -v`: команда удалит том БД.
Если потребуется обновить переменные ИИ в `.env`, пересоздайте `api`:

```powershell
docker compose up -d --force-recreate api
```

**Ограничения:** TXT UTF-8; автоматическая сегментация эвристическая и может
неидеально обрабатывать сокращения и прямую речь. Нет поиска книг в интернете,
автоматического распознавания авторских прав и лингвистической гарантии
качества генерации. Для импорта больших книг предусмотрен лимит 1 МБ и первые
500 подходящих фрагментов. Реальный вызов внешнего ИИ требует действующего
ключа, разрешённого сетевого доступа и оплачиваемого тарифа API.
